## 5. Сетевая архитектура

### Режимы

1. **Локальная сеть** — один игрок Host, остальные находят через `NetworkDiscovery` или вводят локальный IP.
2. **Интернет по IP** — headless-сервер (дома с белым IP или на VPS), подключение по IP/домену, порт `7777/UDP`.
3. **Одиночная игра с ботами** — тот же Host без подключений, боты — серверные игроки. Один код на все режимы (в оригинале логика раздвоена: `MenuGameLocal`/`MenuGame`, `HUD_PWLocal`/`HUD_Multiplayer`).
4. *(Позже, по необходимости)* relay-транспорт (Edgegap / EOS / Light Reflective Mirror), чтобы телефон мог хостить через интернет. Меняется только транспорт.

### Ограничение NAT

| Кто хостит | LAN | Интернет по IP |
|---|---|---|
| Телефон в Wi-Fi | ✅ | ❌ нужен проброс порта |
| Телефон на мобильном интернете | — | ❌ CGNAT оператора |
| ПК с белым IP / проброшенным портом | ✅ | ✅ |
| Выделенный сервер на VPS | — | ✅ |

### Что сделано (MVP)

- `PudgeNetworkManager` (наследник `NetworkManager`) создаётся при старте игры вместе с `KcpTransport` и меню `NetMenu`; сцену трогать не нужно. Сетевые объекты собираются в коде (свои `assetId` и обработчики спавна): герой = префаб `Pudge_Player`/`Pudge_Bot` + `NetworkTransformUnreliable` + `NetHero` + `NetworkIdentity`, одинаково на сервере и клиентах.
- `Simulation.IsProxy` — на чистом клиенте геймплей-компоненты не симулируют (движение, хук, падение, яма, золото, боты), а показывают состояние сервера: `Hookable.ApplyRemoteState`, `HookAbility.ApplyRemoteState`, `HeroInventory.ApplyRemoteState`, `Arena.ApplyRemote*`.
- `NetHero`: SyncVar'ы команды, ника, флагов «жив/падает/пойман», золота и предметов (индексы в каталоге `NetPrefabs`), головки хука (позиция, направление, «летит», «занят», время готовности по `NetworkTime`); `[ClientRpc]` анимаций и «+N монет»; `[Command]` ввода, броска и покупки (сервер сам проверяет кулдаун и золото). Возрождение — `ServerTeleport`, без скольжения из ямы.
- `NetMatch`: счёт обеих команд и объявления серий убийств (с числом рампаг подряд).
- `LocalPlayer` — герой с `PlayerInputController` (в сети его получает только свой герой); HUD, камера и магазин переключаются на него, когда он появляется. `OverlayInput` — пока открыто меню сети, клавиши и мышь не уходят в игру.
- Движение пока без предсказания на клиенте: ввод → сервер → `NetworkTransform` (в LAN задержка незаметна, через интернет — RTT).

### Сетевая модель хука (дальше)

1. Клиент сразу рисует предсказанный хук и шлёт `CmdCastHook(dir, clientTick)`.
2. Сервер проверяет кулдаун/состояние и создаёт компактное состояние `HookState {origin, dir, speed, range, startTick, phase, targetId}`. Клиенты считают позицию хука аналитически — трансформ каждый кадр не синхронизируется.
3. Попадание считает сервер с **компенсацией задержки**: история позиций игроков ~500 мс, откат целей на RTT/2 + задержку интерполяции стреляющего (своя реализация, ~150–200 строк).
4. Попадание → `phase = Pull`, цель в состоянии `Hooked`, позицию ведёт сервер вдоль цепи → у Pudge: убийство, золото, серия убийств, таймер респавна, `[ClientRpc]` для звука и FX.
5. Движение (MVP): владелец двигает себя сам, сервер проверяет скорость и границы зоны команды; остальные интерполируются (`NetworkTransform`). Позже при необходимости — серверное движение с предсказанием.
6. Невидимость (Lotar): скрывать объект от противников на уровне видимости сети (interest management), а не только рендером.
7. `sendRate` ~30 Гц.

## 6. Хостинг headless-сервера на домашнем ПК

1. Узнать WAN-IP в роутере (`http://192.168.0.1`) и сравнить с внешним IP (`curl -4 ifconfig.me` **с выключенным VPN**). Совпадают — белый IP; `100.64–127.x.x` / `10.x` / `172.16–31.x` / `192.168.x` — CGNAT.
2. Белый IP:
   - зарезервировать локальный IP ПК в DHCP роутера;
   - проброс `UDP 7777` → локальный IP ПК;
   - `sudo ufw allow 7777/udp` (если ufw включён);
   - DDNS (DuckDNS / No-IP / встроенный в роутер), т.к. IP скорее всего динамический;
   - сборка **Linux Dedicated Server**, запуск: `./PudgeServer.x86_64 -batchmode -nographics -port 7777` (✅ сборка в batch mode или с `-server` сама стартует сервер и объявляет его в LAN);
   - systemd-сервис для автозапуска и перезапуска.
3. CGNAT — варианты: купить белый IP у провайдера; туннель WireGuard через дешёвый VPS; playit.gg (UDP); Tailscale/ZeroTier (только для друзей). Ngrok и Cloudflare Tunnel не подходят (нет произвольного UDP).
4. **VPN на сервере ломает входящие подключения:** ответы уходят в `tun0` с чужим адресом. Решения:
   - выключить VPN / split tunneling для сервера;
   - или policy routing + привязка сервера к локальному адресу:
     ```bash
     sudo ip route add default via 192.168.0.1 dev wlo1 table 100
     sudo ip rule add from <локальный_IP_ПК> lookup 100
     ```
   - или держать сервер на VPS.
5. Изнутри домашней сети подключаться по локальному IP (NAT loopback на роутере может не работать).
6. Сервер — не от root; все `[Command]` валидировать на сервере (кулдауны, дальность, золото).
7. Перед сборкой игры проверить доступность порта тестовым UDP-эхо-сервером.

Трава из `~/dota_grass` (`Tools/Landscape/build_grass.py`): обычная — зелёные пучки `grass_clump_00*`, детали террейна пятнами на стороне Radiant в меню (густота — в пресетах графики); зимняя — серые тонируемые пучки `grass_clump_02*` с запечённым в текстуру инеем (своей зимней травы в Dota нет: зимние карты так и тонируют), импортирована, но пока не расставлена; текстуры земли из `~/dota_terrain`, тонированные под цвета карты Dota (`Tools/Landscape/tint_terrain.py`: серые оригиналы × настоящий цвет, контраст приглушён; готовые `*_tinted` слишком зелёные и яркие): на арене трава Radiant (`grass_long_01`) на своей стороне, тёмная серо-коричневая потрескавшаяся земля Dire (`sand_cracked001`) на стороне Dire, по краям ямы с обеих сторон — песчаная полоса, как берег реки (`sand_path009`; со стороны Dire — его тёмный песок); в меню у Radiant — трава с пятнами травы с цветами (`grass_long_00`) и мощёная тропинка (`stone_path001_angled`) от камеры к площадке под Пуджем и дальше в лес, у Dire — земля с пятнами `dirt_cracked_patchy_00` и тропинка из каменных плит `stone_path007` (с картой нормалей); карты нормалей в выгрузке пустые — слои без них; на арене зелёная трава на земле Radiant (своя сторона и её холмы), на поле реже, на земле Dire, скалах и в яме — нет. Деревья — не объекты сцены, а деревья компонента Terrain (прототипы и инстансы `TerrainData`) и в арене, и в меню: префабы `Art/Landscape/Trees/Prefabs` — меши FBX, запечённые в один с поворотом и масштабом корня, подмеш на материал, LOD-группа. Конвертация — `Tools/Landscape` (Blender: glTF → FBX, 1 юнит Dota = 1 см).
- ☐ Настоящая карта (меш + коллизии + NavMesh по зонам команд), двухстиковое мобильное управление, кулдаун в UI, маркер цели (`Target_M`), отскок хука от стен, Cinemachine, сложность ботов.
- ☐ Атрибуты и предметы на них: сила, ловкость, интеллект (у героя — значения атрибутов, предметы в магазине их прибавляют).
  - **Интеллект:** боту уменьшает задержку реакции при спасении союзника — и утаскиваемого (`BotBrain.rescueReaction`), и выдёргиваемого из-под летящего хука (`pullOutReaction`) — и поднимает шанс спасения выше базовых 55 % (`rescueChance`); умный бот держит хук в запасе — не кидает его во врага, пока союзник стоит у ямы в досягаемости вражеского хука; игроку магнитит прицел хука к боту, который стоит на месте, — для более быстрого наведения.
  - **Сила:** при спасении (перетягивании) союзника, если сила спасающего хоть на 1 выше силы врага, спасающий перетягивает: союзник спасён полностью, а враг утягивается в яму (сейчас враг тянет союзника дальше, только втрое медленнее — `heldPullSlowdown`).
  - **Ловкость:** прибавляет к скорости передвижения (`PudgeMotor.moveSpeed`) и к скорости, с которой хук тянется обратно (`HookAbility.pullSpeed` / `returnSpeed`).
- ☐ Предмет — улучшение хука «быстрый отцеп»: как только хук стянул врага в яму, он сразу отцепляется и пропадает, а не тащит пустую головку назад к владельцу через яму, — поэтому следующий бросок доступен чуть раньше (перезарядка при попадании и так обнуляется, `resetCooldownOnHit`). Сейчас в `HookAbility.Return()` после сброса цели головка летит обратно на `returnSpeed`; с предметом — сразу `Finish()` / `State.Ready`.
